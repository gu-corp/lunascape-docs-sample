# 2. 要件

## 2.1 機能要件

| ID | 要件 | 優先度 | 検証方法 |
|---|---|---|---|
| REQ-001 | 端末で作成したノートは、接続後 10 秒以内に他の端末へ届く | 必須 | 結合試験 |
| REQ-002 | オフラインで編集したノートは、再接続時に自動で送信される | 必須 | 結合試験 |
| REQ-003 | 同じ版に対する 2 つの更新は競合として検出される | 必須 | 単体試験 |
| REQ-004 | 競合は 3.4 の規則で自動解決し、両方の内容を失わない | 必須 | 単体試験 |
| REQ-005 | 削除は他の端末にも反映され、30 日間はごみ箱から復元できる | 推奨 | 結合試験 |
| REQ-006 | 端末は同期の状態（同期済み、送信中、競合あり）を表示できる | 推奨 | 目視 |

## 2.2 非機能要件

| ID | 要件 | 目標値 |
|---|---|---|
| NFR-001 | 同期 API の応答時間 | 95 パーセンタイルで 300 ms 以内 |
| NFR-002 | 可用性 | 月間 99.9 % |
| NFR-003 | 通信の保護 | TLS 1.3。本文はサーバー保存時に暗号化 |
| NFR-004 | 1 利用者あたりのノート数 | 100,000 件まで性能要件を満たす |

## 2.3 要件の追跡

要件は [構成](03-architecture.md) の各要素と [API](04-api.md) の各エンドポイントに対応づける。対応のない要件は未実装として扱う。

```mermaid
flowchart LR
  REQ001[REQ-001 10 秒以内に届く] --> PUSH[/notes/push]
  REQ002[REQ-002 再接続時に送信] --> QUEUE[端末側キュー]
  REQ003[REQ-003 競合の検出] --> VERSION[版番号の照合]
  REQ004[REQ-004 自動解決] --> MERGE[3 方向マージ]
  QUEUE --> PUSH
  VERSION --> MERGE
```
