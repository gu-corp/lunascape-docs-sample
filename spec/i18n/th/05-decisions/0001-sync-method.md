# ORB-ADR-0001: กำหนดวิธีซิงค์เป็น "เวอร์ชันที่เซิร์ฟเวอร์กำหนดหมายเลขพร้อมการผสานแบบสามทาง"

| รายการ | เนื้อหา |
|---|---|
| รหัสเอกสาร | ORB-ADR-0001 |
| เวอร์ชัน | 1.0 |
| วันที่ปรับปรุง | 2026-07-01 |
| สถานะ | อนุมัติแล้ว |

## 1. ที่มา

โน้ตที่ถูกแก้ไขแบบออฟไลน์บนอุปกรณ์หลายเครื่องจำเป็นต้องบรรจบกัน ตัวเลือกที่พิจารณามี 3 แบบ ได้แก่ (ก) ให้เวลาที่แก้ไขล่าสุดเป็นฝ่ายชนะ (ข) CRDT (ค) หมายเลขเวอร์ชันที่เซิร์ฟเวอร์กำหนดพร้อมการผสานแบบสามทาง

## 2. การตัดสินใจ

| ลำดับ | สิ่งที่ตัดสินใจ |
|---|---|
| 1 | ลำดับตัดสินด้วยหมายเลขเวอร์ชันที่เซิร์ฟเวอร์กำหนด ไม่เชื่อถือนาฬิกาของอุปกรณ์ |
| 2 | แก้ความขัดแย้งด้วยการผสานแบบสามทาง บรรทัดที่ผสานไม่ได้ให้เก็บไว้ทั้งสองฝ่าย โดยให้ความสำคัญกับการไม่สูญเสียเนื้อหา |
| 3 | ไม่เลือกใช้ CRDT เนื่องจากโน้ตมีความยาวสั้น ไม่มีความต้องการแก้ไขพร้อมกัน และไม่คุ้มกับการที่ขนาดเนื้อหาเพิ่มขึ้นเป็น 2 เท่าหรือมากกว่า |

## 3. ผลกระทบ

| ลำดับ | ผลกระทบ |
|---|---|
| 1 | อุปกรณ์ต้องเก็บ `baseVersion` ไว้ และแนบไปด้วยทุกครั้งที่ส่ง |
| 2 | การแสดงความขัดแย้ง (REQ-006) กลายเป็นฟังก์ชันที่อุปกรณ์ต้องมี |
| 3 | เซิร์ฟเวอร์เก็บประวัติย้อนหลัง 30 วัน (สำหรับถังขยะ และเพื่อใช้เป็นฐานของการผสานแบบสามทาง) |
